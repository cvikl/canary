1. Problem
Agents get their tools through MCP servers. A tool's schema tells the agent what arguments to send and what comes back. It says nothing about what the code does to the machine it runs on. A tool can return the right answer and, on the way, read a dot env file, copy an SSH key, and send both somewhere.

2. Who
The people who feel this are the platform and security teams who approve MCP servers for coding assistants. Today their decision is binary. Trust the server, or reject it. No evidence either way.

3. Idea
Canary Cage is a concept for a third option. Plant canaries a tool should never touch. Let an agent write a probe and run it in an isolated cage on Vultr. Watch from outside the cage. Then replay the identical probe under a contract a person approved, and prove the tool still does its job with less authority.

4. Probe
Step one, the agent writes the probe. Vultr Serverless Inference reads the live tool list and writes a short program against a four function harness. Start the server, initialise, list tools, call the tool once, check the result. Our validator parses the syntax tree and accepts or rejects. The accepted probe is hashed and frozen.

5. Runs
Step two, three runs in fresh containers. Run A is the probe without the tool call, the baseline. Run B is the full probe on a private network whose only exit is our recording gateway. Host side strace watches both from outside the container, so nothing inside can tamper with the evidence.

6. Terminal
This is a real run on the Vultr VM. The summary comes back correct. In the same window the host sees the tool read the planted env file, read the SSH key, and post both to a canary host. Our gateway catches the request with the bait in the body.

7. Contract
Step three, the contract. The model proposes the narrowest capability contract that fits the job and the observed matrix. A person approves it. A deterministic compiler turns it into an enforced Docker profile. Run C replays the identical probe by hash. Same summary. Credential reads refused by the operating system. No network to attempt.

8. Solution
What the team gets is a repeatable approval workflow. A capability contract per tool, proof by replay, and an evidence bundle to file. The same loop can gate a registry or run in continuous integration on every new version. Everything ran on one Vultr Cloud Compute VM, with every model call on Vultr Serverless Inference.
